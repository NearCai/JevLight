# 通用实验设定

用同一 JevLight/SUMO benchmark 比较模型原生决策能力及直接上下游协同收益。更换模型、显卡或部署方式时，以下基准和原则保持不变；改变实验语义时应使用独立协议与结果标识。

## 固定基准

| 项目 | 设定 |
| --- | --- |
| 矩阵 | `jinan-1/2/3`、`hangzhou-1/2`、`newyork-1/2` × 普通/Co × 种子 `1/2/3`，每模型 42 个唯一条件；交通流文件保持原样 |
| 仿真 | `start_time=0, count=3600, duration=15`（秒），`eightphase=false`（4 个候选相位） |
| 控制 | `fallback=previous, min_confidence=0.0`；空路口沿用已有本地规则 |
| 请求 | `max_workers=8, jev_retries=3, jev_timeout=120.0, jev_min_interval=0.0` |
| 评估 | `rolling_evaluation=true, hourly_interval=3600, visualize=false, use_wandb=false` |

## 不变原则

- **信息边界**：普通仅本路口当前信息，使用本地压力偏好以及正确的方向、等待时间和容量统计；Co 只增加直接上下游邻居当前状态，启发式排名仅供 Co 参考。两模式均逐路口输入（`packaging=per_intersection`），不输入历史或全网状态，`cojev_history_steps=0`。
- **问题与控制**：默认 `speculative=false`，只问相位。显式开启时在同次请求中追加独立拥堵题，答案仅用于分析，不控制信号；只保留这一开关。
- **原生与完整性**：使用作者原生决策头、编码、校准及发布精度；后端、精度、量化或内核变更须验证。上下文依据实际能力与生产编码确定，覆盖两模式最长请求并留余量，不截断状态、问题、候选或特殊 token。
- **batch**：以同一控制步全部需模型决策的路口为目标，优先一次原生 GPU forward；容量不足时自动分级分块并复用已验证容量。保留各路口独立输入、候选顺序、问题 ID 和映射，全部答案返回后统一执行动作。仅 HTTP 打包、并发或固定小 batch 不代表完成；实际硬件验证且提速后才启用。
- **验收**：普通/Co 分别核对完整输入与映射、真实 GPU 执行、相位及必要 SUMO 动作/指标；CPU/mock 不能替代真实验收，身份匹配时复用有效证据。**不以概率一致性作为验收门槛**：不比较候选概率、拥堵概率或置信度，不设概率差或归一化验收门槛，不为这些差异额外排查。
- **指标与结果**：沿用原 benchmark：AQL 为每采样步网络排队量均值；AWT 为已观测车辆累计停止时间均值；ATT 同时计入到达车辆完整耗时与在途车辆已耗时。保留到达、在途、pending、失败和回退记录，缺失指标不填零，故障场不算成功。保留三种子原始值、均值、样本标准差及普通/Co 成对差；基线独立安排，不作为模型实验依赖。
- **稳定与留存**：正式场期间冻结代码和配置，修复在场次或模型边界应用。每场在 `results/` 保留无密钥配置、原始 `summary.json` 和 `jev_decisions.jsonl`，保留已有合格结果及失败尝试。完成后汇总归档，模型权重、适配器和共享底座不自动删除。
