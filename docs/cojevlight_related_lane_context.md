# Co模式：轨迹识别与中心车道合作视图

当前两模式默认 `speculative=false`，只发送相位Choice题；Noul仅在显式开启时发送。

请求模式标识为 `incoming-side-trajectory-lanes-v6`。

## 关联规则

- 仅 Co 模式使用车辆轨迹识别：以同一车辆 ID 在相邻观测间离开、到达的路口与转向车道建立关联。中间暂时不可见时保留离开标记，直到再次观察到该车辆。
- 仅直行 T、左转 L 参与关联学习与合作视图。观察到右转时会清除该车辆待匹配的旧标记，避免跨过右转路口产生伪关联；不为右转建立合作关系。中心自身已有右转状态仅作本地背景，未改其原有状态范围。
- 每场从零累计转移次数；上下游分别按相应总次数归一化。关联份额必须**严格大于 5%**，不是固定选五个路口，也没有预设的最少车辆数。
- 按每条非空中心 T/L 车道组织 `cooperative_view[lane].upstream/downstream`。邻居车道使用原版默认通信阈值 **0**，只保留当前占用率 **> 0** 的车道。过滤不会删除已学关联。
- 同一路口变道不构成路口合作关系；同一 ID 同时属于多个转向分组时不猜测转向，不累加歧义样本。采样仍沿用既有决策周期；未观测到的转移不补造。
- 关联只来源于观察到的车辆转移，不用方向推断或静态路网连接填充冷启动。空视图可能表示尚未学到、被占用率过滤或当前缺少观测，不能解释为下游必定空闲。

每个邻居条目仅含 `intersection_id`、`lane`、`current_phase`、`state`，其中 `state` 是该车道的当前排队、分段接近车辆、等待、占用率、长度及既有共享车道说明。邻居完整拓扑与启发式排名不进入请求。中心自身排名保留。内部累计记忆用于判断关联；不发送车辆 ID、过去状态、历史动作、变化量或历史提示词，不递归扩展、不全网打包。

- [T/L 共享、累计计数及 connection_threshold=0.05](https://github.com/usail-hkust/CoLLMLight/blob/ce204a90a238e206fa5673b6922aab3a6a9fc597/models/CoLLMLightAgent.py)
- [communication_threshold 默认值为 0](https://github.com/usail-hkust/CoLLMLight/blob/ce204a90a238e206fa5673b6922aab3a6a9fc597/run_CoLLMlight.py#L23)

| 项目 | 原版 | 当前 Co 实现 |
| --- | --- | --- |
| 关联依据 | 车辆 ID 离开/到达匹配 | 相同原则 |
| 车道范围 | 直行/左转 | 相同 |
| 关联筛选 | 累计份额 > 0.05 | 相同，上下游独立计算 |
| 合作视图 | 中心非空车道 → 上游/下游 | 相同组织方式；列表显式保留路口 ID，避免同名车道互相覆盖 |
| 邻居过滤 | occupancy > communication_threshold，默认 0 | 相同默认阈值 |
| 提示词时间信息 | 可包含当前值、变化量与进出统计 | 只发送当前状态 |
| 歧义轨迹 | 最后离开标记匹配 | 保守跳过多转向歧义、同路口变道及右转跨接 |
| 决策接口 | 原版语言模型流程 | 默认使用 JEV Choice；显式开启speculative时追加Noul，沿用既有信号执行流程 |

此实现采用 CoLLMLight 的关联学习与合作视图原则，并保留 Jev 的类型化决策接口。

合成请求夹具覆盖七条交通流的七种状态。夹具通过合成车辆转移预热关联学习器；路网只用于离线构造夹具，不作为运行时关联输入。实际部署需分别验证完整编码、独立映射及普通/Co 的 GPU batch 与 SUMO 行为。
